# 发布验收

自动测试和交叉编译可在 Linux 中完成；下面的真实桌面流程需分别在 Windows x64、macOS arm64 / Intel 上验收。离线预览中的账户、仓库和路径均为测试数据。

## 自动验证

```sh
go test ./...
go test -race ./internal/...
go vet ./...
go run ./cmd/preview -out artifacts
python3 scripts/package.py
```

覆盖仓库地址与特殊路径、私人仓库分页、部分失败、权限和网络错误、账户切换、旧请求回写、重复克隆、取消、真实临时 remote 克隆、目录竞争、记录移除、保存失败、深浅主题、键盘选择及忙碌状态。

## Windows 与 macOS 实机

- [ ] 安装 Git / gh / Codex，解压对应发布包后正常启动；安装包不要求安装 Go。
- [ ] 在已登录 gh 的情况下自动显示正确账户；本人私人仓库能搜索、选择，超过 100 个时仍完整。
- [ ] 切换 gh 账户再刷新，旧账户的仓库不会留下；未登录和网络中断时能重试。
- [ ] 输入 HTTPS 地址和 SSH 地址，选择含中文、空格的父目录，克隆真实私人仓库。
- [ ] 对话框取消后可继续；克隆中取消后无活动 Git 子进程及本次临时目录。
- [ ] 已有同名目录不被改动；克隆中关闭应用能正常停止并清理。
- [ ] 点击“使用 Codex 打开”，在桌面应用中新建聊天且工作目录正确；再次打开最近项目也正确。
- [ ] 卸载 / 禁用 Codex 协议后显示启动失败，代码保留，重新安装后能重试。
- [ ] 重新启动后主题、上次保存位置和最近项目仍保留；移动目录后显示不可用。
- [ ] 移除最近项目记录，磁盘代码仍存在。
- [ ] 640×520、800×640 和系统缩放下均能操作；输入法、下拉键盘选择、Tab 和 Esc 正常。

## 当前验证边界

此环境是 Linux 云端，未提供用户的 GitHub 凭据、Windows / Mac 图形会话或 Codex 桌面应用。自动测试使用真实本地 Git 及离线 UI；这些结果不能替代上面的私人仓库与桌面实机验收。

本地还验证了 Linux / Xvfb 中的原生窗口启动（无 GPU 时使用 MyGO 回退绘制），以及 Windows / macOS 平台测试代码的交叉编译。
